链路为 `X5 ZQWL → 6750 CAN1 → 6750 CAN0 → PC gs_usb → Gazebo Car3`。
两段均为经典CAN 250 kbit/s。上游同一根CAN同时承载11位行走报文
`0x514`和29位ISOBUS报文，不要求另接一根农具CAN；下游为三合一原生协议。
X5只有`isobus_can_mux`独占物理USB，现有差速底盘驱动与ISOBUS客户端共享内部
`vcan73`。`vcan73`只做本机分发，不跨设备绕过6750。

ISOBUS网络管理使用MIT许可的AgIsoStack++，锁定提交
`02f3fe910de5fdc73e2014394c2e80900490b9cc`。应用层是本实验自定义PGN，
不是完整UT/TC实现或AEF认证产品；不能直接宣称与任意商业ISOBUS终端互通。
`0xEF00`为目标地址控制，`0xFF50/52/53/54`为原生农具反馈封装，
`0xFF60/61`为就绪状态和命令应答。设备NAME使用隔离实验身份，不是注册厂商号。

### 协议与保护

- `0x580 Byte0`低半字节风机挡位0～8，高半字节水泵挡位0～8。
- `Byte1–2`为碎枝机0～10000的小端整数；`Byte6`低半字节计数；`Byte7`为前7字节异或。
- `0x5B0`区分植保/碎枝机状态；`0x5B2/3/4`分别保留风机、水泵和碎枝机实际反馈。
- 每通道独立300 ms命令租约，反馈1500 ms超时；重连须先零指令，重复帧不续租。
- 急停/底盘非无人模式/通信故障、农具报警、电机故障、水泵低液位异常会阻止相应输出。
- PC行走与农具授权默认均关闭；喷水场景拒绝未挂载碎枝机的非零指令。
- PC反馈取自Gazebo实际运动和转子关节积分，不把目标转速直接回显成实际转速。

- PC和当前真机卡均保留Ubuntu22.04/ROS2 Humble，不升级Ubuntu版本。
- HPM6750诊断UART已识别阿克曼原生桥接身份。2026-11-05通过原有VCFG接口写入运行选择(machine=18、protocol=514、compute_interface=1)，收到CRC有效的成功应答，generation=1，回读configured=true；没有刷固件。其后再次从X5 ZQWL发送3条全零0x181，PC接收仍为0，6750控制/反馈转发计数均为0，command_age仍未知；物理CAN链路未验收。证据为`hpm-runtime-config-attempt.json`和`can-pc-zqwl-zero-02.json`，不能把USB写成功等同于CAN线上送达。

- 不把CAN回环、软件单元测试或DDS echo当作硬件闭环行驶/采摘测试；真实结果另存运行证据。
