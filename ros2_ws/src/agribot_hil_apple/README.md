## 有线ROS环境

每个HIL进程使用本包的环境，而不是改用户.bashrc或系统默认ROS配置：

```bash
# PC侧（在包目录中）
source scripts/hil_env.sh pc
python3 -m agribot_hil_apple.hardware
python3 -m agribot_hil_apple.wired_probe client --output /tmp/hil-wired.json

# X5侧（在包目录中），先启动此回显节点，再运行PC client
source scripts/hil_env.sh rdk
python3 -m agribot_hil_apple.wired_probe server --timeout 60
```

独立ROS_DOMAIN_ID=73，DDS仅选择有线地址，关闭多播并显式配置对端及本机地址。不禁用Wi-Fi，SSH管理可继续走Wi-Fi。跨机ROS数据不能选择Wi-Fi作为备用链路；网线断开时通信应失败而不是悄悄切到无线。

PC如开启UFW，只需允许直连接口上来自192.168.1.102的UDP 25650:25899（域73、参与者0–119），不要关闭全局防火墙。

2026-11-05实测：PC向X5发送100条、每条16 KiB的探测消息并校验回传内容，100条全部收到；往返延迟中位数6.42 ms、P95为7.02 ms。对域73的抓包中，有线接口1232包、本机回环358包、Wi-Fi接口0包。此结果是本次通信测试，不是单向传感器延迟，也不表示已验证高带宽相机/点云负载。证据保存在PC的`~/.local/state/agribot-hil-20261105/`。

PC的NetworkManager连接`agribot-hil-x5`已设置有线静态地址及自动连接，不设置默认网关；X5沿用原卡的`192.168.1.102`。互联网、Wi-Fi热点及原真机ROS域0均未切换。后续HIL启动脚本必须显式加载上述有线环境，不能只依赖终端中偶然存在的环境变量。

## CAN准备

```bash
# PC，仅在接口DOWN且总线未运行任务时
sudo bash scripts/prepare_can.sh can0 003000224856511520343739
# X5的ZQWL盒由已有真机驱动初始化，不用ip link配置板载can0
```

工具会核对gs_usb驱动和USB序列号；拒绝其他驱动、错误序列号及已激活的总线。配置接口不会发送应用CAN帧。总线UP、驱动已加载、6750身份可读均不等于CAN透明转发已验收，仍需逐字节的双向实物链路验证。

初始化使用`restart-ms 0`，兼容PC端不支持自动bus-off恢复的gs_usb版本；发生bus-off须先排查接线/终端电阻并显式恢复，不能在后台自动恢复后继续旧命令。

## 大消息传输与运行验证

PC与X5已安装`/etc/sysctl.d/99-agribot-hil-network.conf`，由开机的`systemd-sysctl`
将收发缓冲上限设为16MiB，不改变默认缓冲、网卡地址或路由。新机器可将本包同名config文件
以root所有、0644权限安装到该位置，再用`sudo sysctl -p /etc/sysctl.d/99-agribot-hil-network.conf`
应用。`sudo bash scripts/prepare_network.sh`仍可用于临时检查并向上调整上限，不修改持久配置。
私有CycloneDDS XML请求8MiB接收缓冲，
并限制单个DDS报文1400B、分片1200B，避免1500B MTU上的IP分片重组失败。

`/hil/camera/image/compressed`，X5解码为 `/hil/camera/decoded` 供FAST-LIVO2读取；保留采样时间戳。
实测53组跨机往返配对图像的编码、尺寸、步长及像素字节全部一致。未降分辨率或改成有损JPEG。

## 环境与边界

- PC和当前真机卡均保留Ubuntu22.04/ROS2 Humble，不升级Ubuntu版本。
- HPM6750诊断UART已识别阿克曼原生桥接身份。2026-11-05通过原有VCFG接口写入运行选择(machine=18、protocol=514、compute_interface=1)，收到CRC有效的成功应答，generation=1，回读configured=true；没有刷固件。其后再次从X5 ZQWL发送3条全零0x181，PC接收仍为0，6750控制/反馈转发计数均为0，command_age仍未知；物理CAN链路未验收。证据为`hpm-runtime-config-attempt.json`和`can-pc-zqwl-zero-02.json`，不能把USB写成功等同于CAN线上送达。
- 当前项目的6750接线要求是算力侧CAN1(PE31/J11[7] TX、PE30/J11[10] RX，经外接3.3V CAN收发器)、执行器侧板载CAN0。不能把CANH/CANL直接接到TX/RX逻辑引脚；两侧需要正确共地与终端电阻。当前接线照片/外接收发器状态尚待确认。
- PC的CH340诊断串口被brltty误占用，2026-11-05已恢复。仅对实验台USB口1-4.3上的1a86:7523增加排除，不卸载全局无障碍软件；更换USB口需重新核对。
- 不把CAN回环、软件单元测试或DDS echo当作硬件闭环行驶/采摘测试；真实结果另存运行证据。
