## 可执行程序按钮链路

在正式新程序中选择 Car1，实际安装四类装备，选择上述默认组合，点击“导出并运行仿真”完成：

1. 生成独立 `ConfigExports/unity_car1`，导出 64 个网格。
2. 导入 ROS 配置并增量编译，启动 Gazebo 和 RViz。
3. 生成 3032 点连续路径，在 1.100 s 内完成经过全部 23 个预设点的规划；验证通过后才向控制器下发路径。
4. RViz 显示新车及规划路径，未叠加旧车零件。
5. 点击“停止仿真”，界面和脚本返回停止成功，仿真主进程退出状态为 0；随后确认本次 Unity、Gazebo、RViz 和 ROS 进程全部退出。

停止过程中部分 Python 节点因 ROS 上下文关闭打印退出异常，这些发生在主动中断之后，不是本次运行期间的定位或规划失败。GUI 检查不是全路线完成测试。测试后已恢复 GUI 检查前的装备与算法偏好状态。

## 补充：传感器安装点击回归

用户进一步要求核实所有车型的安装点击功能。前面的 PlayMode 两例只验证了按钮、装备条目和导出入口，实际鼠标完整安装当时仅检查 Car1，不能据此保证每辆车全部安装交互都正常。

补测复现并修复了以下问题：

- 新场景的装备按钮采用底部锚点，而导出按钮采用顶部锚点，某些窗口尺寸下两者重叠。已统一锚点并保留按钮外观；非交互文字不再拦截点击。
- 新车卸下动画尚未结束时立即重新安装，原来的淡出回调仍会隐藏物体。现在重新安装会取消卸下动画，并恢复原始缩放和颜色。
- 装备详情的非交互图片、文字不再参与 UI 点击拦截。
- 实际程序出现空库存存档，初始化会接受这个空列表并一直显示空装备面板。两个场景现在都按固定装备库补齐可选条目，不再让空存档或旧存档删除四类固定装备；安装状态仍与可选库存分开，新开会话默认未安装。

新增测试使用实际场景的 GraphicRaycaster 和 PointerDown/PointerUp/PointerClick 路由，不用直接调用按钮 onClick 来绕过遮挡检查。覆盖六辆车、四类传感器的选择、安装、卸下、快速重新安装、安装完成后位置/旋转/缩放恢复、面板重开、返回重选和跨车操作隔离。另用空库存存档测试恢复，连续三次切换新车场景和原阿克曼场景检查装备库保留。

最新整组 PlayMode 结果：**11/11 通过，192.73 s**。这是 UI 点击与状态回归，不是新增全路线运动或真实传感器外参标定验收。
