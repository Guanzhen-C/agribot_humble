# Unity 履带差速车控制适配与验证

日期：2026-10-13。车型：`unity_car3`。本次仅适配 Unity 导出的名义仿真履带车，不改真机运行参数，不宣称完整长路线或所有算法组合均已验收。

## 控制器选项

Unity 中仍选择原来的 MPPI、RPP、DWB，不增加重复算法名称。ROS 根据导出车辆的 DiffDrive 模型自动加载 `agribot_vehicle_description/config/differential_controllers.yaml`。

| 控制器 | 差速配置 |
| --- | --- |
| MPPI | DiffDrive，删除阿克曼曲率约束；角速度采样标准差 0.08 rad/s，角加速度 0.30 rad/s²；终点朝向评分范围 0.25 m |
| RPP | 启用朝向调整，最小前视距离 0.5 m；若启用倒车则关闭朝向调整，避免 Humble RPP 的冲突组合 |
| DWB | 标准差速轨迹生成器、横向速度为 0、RotateToGoal 评分；角加速度 0.30 rad/s² |

最大线速度和角速度、正反向允许条件、车体轮廓和缓冲尺寸继续从 Unity 导出配置读取，未覆盖成另一辆真车的数值。当前 Car3 最大线速度约 0.30 m/s、最大角速度约 0.60 rad/s。差速终点检查使用 SimpleGoalChecker，位置容差 0.25 m、航向容差 0.20 rad。

感知、定位仍为 STVL、FAST-LIVO2 + RTK；规划仍为 Smac Hybrid-A*，没有本轮更换成 State Lattice。碰撞检测保持开启。四个隐藏接触轮的等效履带动力学和原摩擦参数保持，未改成直接设置车辆位姿的运动方式。

阿克曼分支没有应用差速覆盖配置；原 canonical 与 generated 文件的本轮前修改时间均为 12:54，本轮没有重新导入原车。与最初 10:01 备份相比已有之前视觉/导出阶段的差异，不能称整个目录仍逐字节一致。

## 使用

在 Unity 中选择履带车，完成四类装备安装，选择 MPPI、RPP 或 DWB 后点击“导出并运行仿真”。不用手工选运动模型，仍自动启动原来的 23 点任务；正常启动不会使用本次短程测试路径。

原默认选项保持 MPPI。三种控制器均可供后续对比，但不能仅根据这些冒烟结果评定哪个全程精度最高。

证据目录：`/home/cgz/.local/state/agribot-multivehicle-validation/20261013/differential_controllers/`。成功目录为三个 `*_orchard_smoke`、三个 `*_curve_follow` 和 `ackermann_regression`；失败对照目录也保留，没有覆盖为成功结果。测试结束时所有本轮仿真进程已退出，没有启动真机底盘。

参数依据已核对 Nav2 Humble 的 [RPP 实现](https://github.com/ros-navigation/navigation2/blob/humble/nav2_regulated_pure_pursuit_controller/src/regulated_pure_pursuit_controller.cpp)与 [DWB RotateToGoal 实现](https://github.com/ros-navigation/navigation2/blob/humble/nav2_dwb_controller/dwb_critics/src/rotate_to_goal.cpp)，以及项目现有差速真机 MPPI 配置；名义仿真速度和尺寸仍由当前车型导出值决定。
